## 0. TL;DR

**一句话结论**：这不是「退出时崩了」，而是「退出没跟系统打招呼」。
本项目交付 `.nro`（`envIsNso()==false`），却在 `SDL/SDLMain.cpp` 里强制声明 `AppletType_Application`；
libnx 的 `_appletCleanup` 默认只在 `(envIsNso() && __nx_applet_exit_mode==0) || __nx_applet_exit_mode==1`
时注册 `_appletExitProcess`（向 AM 发 `ISelfController cmd 0 Exit` 的退出握手）。
weak 默认值 `__nx_applet_exit_mode=0` 让 NRO 下整个握手被跳过，HOS 收不到握手 → 判为异常 applet 终止 → 弹框。

**最终修复**（`c91f6fd59e`，一个强符号 + 三件配套）：

```c
// SDL/SDLMain.cpp，与 __nx_applet_type 放在同一个 extern "C" 块里
extern "C" {
u32 __nx_applet_type = AppletType_Application;
size_t __nx_heap_size = 0;
u32 __nx_applet_exit_mode = 1;   // 强符号覆盖 applet.o 的 weak 默认值 0
}
```

配套三件事，缺一不可：teardown 里**保留 `appletExit()`**；`__nx_exit(0, envGetExitFuncPtr())`
的第二个参数**就地求值**、绝不缓存；sdmc 日志**全程可写**且收尾前显式 `fclose` 落盘。

### 已推翻、绝不要重试的 6 条

|---|---|---|
| 1 | `__nx_exit(0, nullptr)` | `switch_crt0.o::__nx_exit` 是 `mov sp, __stack_top; br x1`，**没有 NULL 检查**。第二参为 NULL 就是跳到地址 0。必须传 `envGetExitFuncPtr()`。 |

## 1. libnx 4.12.0-1 退出链事实

### 1.1 本机没有源码树，结论怎么来的

本机 devkitPro 只装了 `include/` 和 `libnx.a`，**没有 libnx 源码树**。
所有事实都是把归档里的目标文件拆出来反汇编得到的，任何人都能复现：

```bash
cd "$(mktemp -d)"
aarch64-none-elf-ar x /c/devkitPro/libnx/lib/libnx.a init.o switch_crt0.o applet.o env.o

aarch64-none-elf-objdump -dr init.o           # __libnx_exit / __appExit
aarch64-none-elf-objdump -dr switch_crt0.o    # __nx_exit
aarch64-none-elf-objdump -dr applet.o         # _appletCleanup / _appletExitProcess / appletExit
aarch64-none-elf-objdump -dr env.o            # envIsNso / envGetExitFuncPtr / envSetExitFuncPtr
aarch64-none-elf-nm applet.o                  # V __nx_applet_exit_mode（weak object）
```

版本：`libnx 4.12.0-1`。相关公开头文件：`switch/runtime/env.h`、`switch/kernel/svc.h`。
下文的反汇编均为**节选**，省略的指令以 `...` 标出，重定位行保留以便对照。

### 1.2 `init.o::__libnx_exit` —— 忽略 rc

```asm
0000000000000000 <__libnx_exit>:
   0:  stp x29, x30, [sp, #-16]!
   4:  mov x29, sp
   8:  bl  __appExit                 ; R_AARCH64_CALL26
   c:  bl  envGetExitFuncPtr        ; R_AARCH64_CALL26
  10:  mov x1, x0                   ; 第二参 = 返回函数指针
  14:  mov w0, #0x0                 ; 传入的 rc 被丢弃，退出码恒 0
  18:  bl  __nx_exit
```

`__libnx_exit` 的入参 rc 没有任何用途，`__nx_exit` 也不带 code。
`__nx_exit` 之前**不经过 `envExit`**——第 3 条错误方案就是被这段反汇编推翻的。

### 1.3 `init.o::__appExit` —— 默认 8 步顺序（weak）

```asm
0000000000000000 <__appExit>:
  ...  adrp/ldr x0, userAppExit   ; GOT，weak，为 NULL 则跳过
       cbz  x0, +8
       bl   userAppExit
  ...  adrp/ldr x0, __nx_win_exit ; GOT，weak，为 NULL 则跳过
       cbz  x0, +8
       bl   __nx_win_exit
       bl   fsdevUnmountAll
       bl   fsExit
       bl   timeExit
       bl   hidExit
       bl   appletExit
       b    smExit                  ; 尾调用
```

八步固定为：`userAppExit` → `__nx_win_exit` → `fsdevUnmountAll` → `fsExit` → `timeExit`
→ `hidExit` → `appletExit` → `smExit`，之后由 `__libnx_exit` 调 `__nx_exit(0, envGetExitFuncPtr())`。

- 默认链里**没有** `nifmExit / audinExit / audoutExit / nvExit / plExit / romfsExit / socketExit`；
  往 teardown 里加这些二次 close 是本项目一直在躲的坑（见 `docs/switch/pitfalls.md` 的 apm 双关说明）。
- `__appExit` 本身是 weak，所以我们可以用**强符号**覆盖它、插入逐句埋点而不改变这 8 步的相对顺序。
  这是整轮排障能做出来的前提。

### 1.4 `switch_crt0.o::__nx_exit` —— 汇编，无 NULL 检查

```asm
00000000000000e0 <__nx_exit>:
  e0:  adrp x8, __stack_top
  e4:  ldr  x8, [x8]
  e8:  mov  sp, x8
  ec:  br   x1                      ; x1 = 第二参；为 0 就跳到地址 0
```

- 先恢复栈顶，再 `br x1`；**没有 NULL 检查、没有退出码、没有 svc 调用**。
- `switch/kernel/svc.h:529` 明确是 `void NX_NORETURN svcExitProcess(void);` —— 无参。
- 所以 `__nx_exit(0, nullptr)` 必跳地址 0；`svcExitProcess(0)` 连编译都过不去。

### 1.5 `envGetExitFuncPtr()` 对 NRO / NSO 的语义

```asm
<envGetExitFuncPtr>:  adrp x0, g_loaderRetAddr ;  ldr x0, [x0] ; ret
<envSetExitFuncPtr>:  adrp x1, g_loaderRetAddr ;  str x0, [x1] ; ret
<envIsNso>:           adrp x0, g_isNso         ;  ldrb w0,[x0] ; ret
```

`envGetExitFuncPtr()` 只是读全局变量 `g_loaderRetAddr`，**本身与 NSO/NRO 无关**：
`envSetup()` 时由 loader 传入 `saved_lr`（`typedef void NX_NORETURN (*LoaderReturnFn)(int result_code);`），
NSO 下是 loader 返回地址，NRO 下由 hbloader 提供同一语义的返回函数。

真正的差别在 `applet.o`：`_appletCleanup` 会用 `envSetExitFuncPtr(_appletExitProcess)`
**替换**这个指针，而替换是否发生取决于 `envIsNso()` 与 `__nx_applet_exit_mode`。
`envIsNso()` 读的是 `g_isNso` 字节，NRO 下为 0。

### 1.6 `_appletCleanup` 的注册条件与两阶段行为

`applet.o` 反汇编（0x24–0xa0）：

```asm
  24:  bl   envIsNso
  28:  adrp x1, __nx_applet_exit_mode ; GOT（weak object，默认 0）
  30:  ldr  w1, [x1]
  34:  tbz  w0, #0, 98       ; !envIsNso()  -> 跳 0x98
  38:  cbnz w1, 98           ; mode != 0    -> 跳 0x98
  3c:  ...                   ; 注册路径（检查 __nx_applet_type，最终 envSetExitFuncPtr）
  98:  cmp  w1, #0x1
  9c:  b.eq 3c               ; mode == 1    -> 也进注册路径
  a0:  ...                   ; 否则跳过注册
```

即注册条件精确为 **`(envIsNso() && mode==0) || mode==1`**。
`aarch64-none-elf-nm applet.o` 显示 `V __nx_applet_exit_mode`（weak object，默认在 .bss 为 0），
所以一个强符号 `u32 __nx_applet_exit_mode = 1;` 就能覆盖；对 NSO 是行为等价的 no-op（原本 `true && 0` 已成立）。

还有一层：`appletExit()` 只在 `g_appletGuard` 引用计数减到 0 时才调用 `_appletCleanup`：

```asm
<appletExit>:
  ...  mutexLock(&g_appletGuard)
       ldr  w1, [x0, #4]     ; refcount
       cbz  w1, 38
       sub  w1, w1, #1
       str  w1, [x0, #4]
       cbnz w1, 38
       bl   _appletCleanup    ; 仅归零这一次
  38:  b    mutexUnlock
```

诊断代码里那个「最多补调 8 次 `appletExit()`」的循环，就是为了把启动阶段其他 `appletInitialize()` 留下的
额外引用计数打光。

**两阶段行为**：

1. `_appletCleanup`（在 `appletExit()` 内、refcount 归零时）把 `_appletExitProcess` 写进
   `g_loaderRetAddr`，并置 `g_appletExitProcessFlag` / `g_appletLeftInitialized`；
2. `__nx_exit` 的 `br x1` 跳进 `_appletExitProcess`：

```asm
0000000000000000 <_appletExitProcess>:
   0:  stp x29, x30, [sp, #-16]!
   8:  bl  appletInitialize
   c:  bl  appletExit          ; 二次进入，向 AM 发 ISelfController cmd 0 Exit
  10:  ldr w0, g_appletExitProcessResult
  18:  cbnz w0, 20
  1c:  bl  _appletInfiniteSleepLoop   ; 成功：睡死，等 AM 正常回收进程
  20:  bl  svcExitProcess
```

**没有第 1 阶段**，`br x1` 就直接回到 loader，AM 从未收到 applet 的退出请求，
HOS 判为异常 applet 终止 → 弹框。这就是全部根因。

**两条贯穿全过程的认知，别再弄反**：

1. **atexit 钩子先于静态析构执行**。atexit 钩子与静态析构共用一张表、按注册**逆序**执行：
   静态析构在 `main()` 之前就注册好了，所以最后执行；第 1 轮在 `main()` 里注册的 atexit 钩子反而先跑。
   旧注释误以为它「在所有静态析构之后」，实际它打印完才轮到静态析构。所以日志停在
   `[exit] atexit: ... static destructors next` 说明崩在静态析构，而不是崩在 `__appExit`。
2. **`_exit(0)` 跳过全部 atexit / 静态析构 / newlib exit-time cleanup，但仍会走我们的 `__appExit` 强符号埋点版**
   （链：`_exit` → `__syscall_exit` → `__libnx_exit` → `__appExit` → `__nx_exit`）。
   第 2 轮正是靠这一点，把「静态析构」和「libnx teardown」两个嫌疑分开。

## 3. 诊断方法论

### 3.1 硬要求：日志埋点必须全程可写

第 4 轮的教训最贵：为了恢复标准 teardown，在 `__appExit` 开头先 `fclose` 了日志，
结果后面所有诊断行一条都落不了盘，白跑一轮真机。

具体约束：

- **日志对象必须活过静态析构**：`s_switchLogLock` 用 `new std::mutex()` 堆分配并故意泄漏，
  不能写成函数内 `static std::mutex`（会在静态析构阶段被销毁，之后 `lock_guard` 是 UB，
  真机表现就是日志中途断掉 + 弹框）。cookie `FILE*` 同理，file-scope 且全程不 close。
- **诊断输出一律 `printf` 直通**，不要用 `INFO_LOG(Log::sceNet)` 之类会被通道级过滤的日志宏
  （见 `docs/switch/pitfalls.md` F13：打印了但看不见，会误判「代码没跑」）。
- **每个关键调用打一对 `begin` / `done`**，中间 `fflush(nullptr)`；
  再在 teardown 开头打一条固定 **baseline**（`[exit] __appExit: enter`、
  `[exit] pre-appletExit exitFuncPtr=%p ...`）。
- **不要为了「避免崩溃」把日志关掉**。宁可跳过会崩的 teardown 步骤，也要保住写路径
  （HOS 会在进程终止时回收残留的 fs handle，跳过是安全的）。

### 3.2 `fflush(nullptr)` 只推到 IPC，落盘要 `fclose`

`fflush(nullptr)` 只是把 stdio 缓冲推到 devoptab 的 `fsFileWrite` IPC；
`fsp-srv` 可能仍让 FAT 目录项里的文件大小是旧的，事后读卡会**缺最后 1–2 行**。

因此最终代码在 `__nx_exit` 之前显式关流：

```c
printf("[exit] __appExit: closing sdmc log to commit final traces\n");
fflush(nullptr);
SwitchCloseLogForTeardown();      // 内部 fflush(raw) + fclose(raw)，提交 FAT 目录项
__nx_exit(0, envGetExitFuncPtr());
```

前提是 `fsExit()` / `fsdevUnmountAll()` 都被跳过、fs 会话仍活着，`fsFileClose` 才会成功。
顺序反了（先 `fsExit()` 再 `fclose`）等于白写。

### 3.3 日志停在 `begin` 没有 `done` ≠ 一定崩在那里

有两种可能，靠 **baseline 行**区分：

| 现象 | 判读 |
|---|---|
| baseline 之后的 `begin` 有、`done` 没有，且**后续任何行都没有** | 可能是崩点，也可能是写路径失效，不能直接下结论 |
| 先确认 baseline 存在（说明已经进到 teardown） | 排除「崩在 main / 静态析构」 |
| 把怀疑会关 fs 会话的调用（如 `fsExit()`）跳过复跑，日志能继续往下出 | **写路径失效**，不是崩溃。第 6 轮 09:03 日志就是这个情况：`[exit] fsExit: begin` 后无 `done`，跳过后诊断行一路出到 `appletExit` |
| 跳过之后仍停在同一句、且不弹新日志 | 才是真崩点（第 3 轮的 `fsdevUnmountAll()`） |

一句话：**「日志停了」是观测失效或崩溃的并集，先证明写路径还活着，再谈崩点。**

## 4. 根因与修复细节

### 4.1 强符号定义

```c
// SDL/SDLMain.cpp
#define LIBNX_SWKBD_LIMIT 500 // enforced by HOS
extern "C" {
u32 __nx_applet_type = AppletType_Application;
size_t __nx_heap_size = 0;

// libnx weak symbol (applet.o), default 0. _appletCleanup only registers
// _appletExitProcess (the ISelfController cmd 0 Exit handshake with AM) when
//   (envIsNso() && __nx_applet_exit_mode == 0) || __nx_applet_exit_mode == 1
// We ship an NRO (envIsNso()==false) while forcing AppletType_Application above,
// so with the default 0 the AM exit handshake is never established and HOS
// reports an abnormal applet termination on quit. Force mode 1.
u32 __nx_applet_exit_mode = 1;
}
```

只需这一个符号。对 NSO 是行为等价的 no-op，对 NRO 才补上缺失的握手。
不要用「改 `__nx_applet_type`」或「改用 NSO 交付」去绕——前者会让 swkbd / XMB 主机身份判断全部失真，
后者不是本项目的交付形态。

### 4.2 `__appExit` 最终 teardown 顺序与诊断埋点

下面是最终代码的**精简摘录**（省略了逐句重复的 `printf` / `fflush(nullptr)`）：

```c
extern "C" void __nx_exit(int rc, LoaderReturnFn exit_func);   // 不在 libnx 公开头文件里

extern "C" void __appExit(void) {
    static bool done = false;
    if (done) return;
    done = true;                       // 防二次 teardown
    printf("[exit] __appExit: enter\n"); fflush(nullptr);

    __nx_win_exit();                   // nwindow / vi / display（我们自己的强实现）

    // 运行时诊断：一次记录环境，确认 NRO + Application 的组合
    printf("[exit] diag: envIsNso()=%d appletGetAppletType()=%d __nx_applet_type=%d\n",
           (int)envIsNso(), (int)appletGetAppletType(), (int)__nx_applet_type);

    /* fsdevUnmountAll()  SKIP：sdmc 上还有打开的日志 FILE*，真机必崩 */
    /* fsExit()            SKIP：sessionmgrClose 关掉日志写路径依赖的 fs 会话 */

    timeExit();
    hidExit();

    // AM 握手探针：retBefore/retAfter 只用于打印，绝不传给 __nx_exit()
    LoaderReturnFn retBefore = envGetExitFuncPtr();
    appletExit();                      // refcount 归零时触发 _appletCleanup -> envSetExitFuncPtr(_appletExitProcess)
    LoaderReturnFn retAfter  = envGetExitFuncPtr();
    for (int pass = 2; pass <= 8 && retAfter == retBefore; ++pass) {
        appletExit();                  // 打光启动期其他 appletInitialize() 留下的引用计数
        retAfter = envGetExitFuncPtr();
    }
    printf("[exit] appletExit: handshake %s\n",
           retAfter != retBefore ? "established" : "MISSING (guard refcount never reached 0)");

    smExit();

    // IRON RULE：envGetExitFuncPtr() 必须在所有 appletExit()/smExit() 之后就地求值
    printf("[exit] __appExit: closing sdmc log to commit final traces\n");
    fflush(nullptr);
    SwitchCloseLogForTeardown();       // 显式 fclose，提交 FAT 目录项
    __nx_exit(0, envGetExitFuncPtr());
    __builtin_unreachable();           // __nx_exit 实际是 br x1，不会返回
}
```

三条 IRON RULE（对应 TL;DR 里第 1、5、6 条错误方案）：

1. `__nx_exit` 第二参**就地** `envGetExitFuncPtr()`，且必须在 `appletExit()` / `smExit()` **之后**；
   缓存旧值会绕过握手。
2. `appletExit()` 绝不能删，且要保证 `g_appletGuard` refcount 真归零（循环上限 8 是防死循环的硬界）。
3. 只跳 `fsdevUnmountAll()` 与 `fsExit()` 两个 fs 层调用；`timeExit / hidExit / appletExit / smExit`
   按 libnx 默认相对顺序保留。

> 注：`SDLMain.cpp` 里有少量注释沿用中间轮次的说法（例如把 `SwitchCloseLogForTeardown`
> 标成 `unused`、以及按旧的硬件轮次编号描述 round 3/4）。**以实际调用点与本文第 2 节表格为准**，
> 别被这些注释带偏。

## 6. 给后来人的检查清单

改退出路径前逐项核对，任何一项不满足都别上真机：

1. `aarch64-none-elf-nm` 最终 ELF 里是 **`D __nx_applet_exit_mode`**（不是 `V`），
   `objdump -s` 读值为 `01 00 00 00`。
2. `__nx_exit(0, envGetExitFuncPtr())` 的第二个参数**就地求值**，位于所有
   `appletExit()` / `smExit()` **之后**；任何形式的提前缓存都删掉。
3. `appletExit()` 保留在 teardown 里；若 `retAfter == retBefore`，用带上限（8）的循环补调
   `appletExit()` 直到打印 `handshake established`。缺 `appletExit()` = 必弹框。
4. `timeExit / hidExit / appletExit / smExit` 保持 libnx 默认相对顺序；
   不要往 teardown 里加 `nifmExit / audinExit / audoutExit / nvExit / plExit / romfsExit / socketExit`
   等默认 8 步之外的 Exit（二次 close 是本项目一直在躲的坑）。
5. `fsdevUnmountAll()` / `fsExit()` 在 sdmc 日志 `FILE*` 仍打开时**一律跳过**。
   若将来必须恢复，顺序是：先 `SwitchCloseLogForTeardown()`，再 `fsdevUnmountAll()`，不能反。
6. 日志全程可写：锁用 `new` 堆分配（不可被静态析构）、诊断用 `printf` 直通、
   关键调用成对 `begin` / `done` + `fflush(nullptr)`、收尾前显式 `fclose` 提交 FAT 目录项。
7. 判读日志先找 baseline：停在 `begin` 无 `done` 时，先跳过疑似关 fs 会话的调用复跑，
   区分「写路径失效」与「真崩点」，不要直接把停住的那句当成崩溃位置。
8. 验收四件套齐全才算完成：`nm` 强符号 + `objdump` 值为 1 + 编译 zero error / exit 0 +
   **真机冷启动 ≥3 次退出不弹框**（且日志出现 `handshake established`）。
